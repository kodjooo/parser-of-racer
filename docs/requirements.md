Race Monitor (Portugal + Spain) — бизнес-требования
=================================================

1) НАЗНАЧЕНИЕ
-------------------------------------------
Один сборщик находит беговые мероприятия Португалии и Испании, сравнивает их
с общей RACES и формирует один список кандидатов Missing races с COUNTRY.
Это поиск отсутствующих в таблице мероприятий, а не проверка публикации в WP.
Сборщик не изменяет RACES, не создаёт карточки на сайте и не вызывает издатель.
Подробности, цены, варианты и описания по-прежнему заполняются в прежнем процессе.

2) ЧЕТЫРЕ ИСТОЧНИКА
-------------------------------------------
- portugalruncalendar.com: прежний обход календаря и карточек через Playwright;
  внешняя ссылка, название и координаты, проверка страны через OpenCage.
- portugalrunning.com: WordPress REST, предварительный отбор по году/известным
  названиям, per-event iCal для будущих дат и локаций, внешняя регистрационная
  ссылка через прежний браузерный адаптер (или каноническая ссылка как fallback).
- Running.life: HTTP-календарь Испании с полной пагинацией, события JSON-LD.
- RockTheSport: публичный HTTP API, вся пагинация испанских беговых дисциплин.

Существующие алгоритмы стран сохраняются; новые агентские сценарии, сбор PDF,
цен/вариантов и автоматическая публикация в эту задачу не входят.

3) СРАВНЕНИЕ И СТРАНА
-------------------------------------------
COUNTRY участвует в сравнении с RACES. Старые строки с пустой страной относятся
к PT; ES требует явной страны. Выходные значения — Portugal/Spain.
Дедупликация по прежним правилам страны: нормализованные URL, названия с годом;
для ES также дата издания и подтверждение географии при сравнении разных ссылок.
Сбой источника не должен менять приоритет выбора ссылки уже известного события.

4) ЕДИНЫЙ СПИСОК И СОХРАНЕНИЕ ИСТОРИИ
-------------------------------------------
Вкладка Missing races: COUNTRY, Источник, Название, Дата, Ссылка, Координаты,
Регион, Город. Поля, которых исходный адаптер не получает, остаются пустыми.
Список содержит все текущие отсутствующие в RACES события, в том числе те,
о которых ранее уже уведомляли. Повторная обработка не добавляет копии строк.
Один запрос заменяет диапазон и очищает старый хвост; clear() до записи запрещён.

При переходе сохраняются полные исходные JSON-истории и снимки обоих списков.
Старая PT-вкладка дублируется в скрытый архив, прежняя ES-вкладка архивируется
без удаления. Общая вкладка сохраняет прежний PT gid и получает COUNTRY-фильтр.
Миграция не должна выполняться повторно поверх существующей общей истории.

5) УВЕДОМЛЕНИЯ
-------------------------------------------
Один ежедневный Telegram-дайджест в существующий настроенный чат:
число кандидатов PT/ES, сколько обнаружено впервые, ошибки источников и ссылка
на общий список. Не нужно отдельного сообщения для каждой страны/каждого забега.
История уведомлений сохраняется в JSON на постоянном томе; старые PT URL-ключи
сохраняют прежнюю семантику, новые ключи включают страну, URL и доступную дату.
Пометка об уведомлении — только после успешной отправки. Повторный проход
в тот же день обновляет список без второго дайджеста; при неудачной отправке
события остаются неуведомлёнными. Авторизация Telegram неинтерактивная.

6) ОШИБКИ И РАСПИСАНИЕ
-------------------------------------------
Каждый источник работает в отдельном процессе с ограничением времени.
Ошибка одного адаптера сохраняет его прежний результат, остальные продолжаются.
Неожиданно пустой результат вместо непустого кэша считается ошибкой и не стирает
список. Ошибки видны в общем дайджесте и локальном JSON-отчёте.

Общий Docker-сервис запускается ежедневно в 00:15 Europe/Moscow. По умолчанию
первый запуск контейнера не запускает сбор немедленно. День завершённого прохода
сохраняется: после рестарта он не повторяется, пропущенное расписание догоняется.
restart unless-stopped восстанавливает сервис после сбоя/перезапуска Docker.
Параллельные проходы запрещены файловой блокировкой, JSON пишется атомарно.
Healthcheck проверяет свежесть последнего прохода (36 часов); логи ограничены.
Старые отдельные PT/ES-контейнеры после перехода остановлены и не перезапускаются.

7) ПРОВЕРКА
-------------------------------------------
DRY_RUN обходит реальные источники и читает RACES, сохраняя только локальный
диагностический отчёт; Google Sheets, историю уведомлений и Telegram не меняет.
Нужны регрессия в рабочем Docker-образе, проверка четырёх реальных источников,
сохранности старой истории, повторной обработки, одной реальной доставки
Telegram и перезапуска общего контейнера без повторного прохода/уведомления.
Публикация мероприятий и её расписание не должны меняться при этих проверках.
