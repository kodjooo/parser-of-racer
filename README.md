# Race Monitor (Portugal + Spain)

Общий сборщик четырёх источников PT/ES: одна вкладка Missing races с COUNTRY и одно ежедневное уведомление в Telegram.

## Общий рабочий режим PT/ES

Используйте `race-monitor-unified` (`MONITOR_COUNTRY=both`). Старые PT/ES-сервисы
оставлены в профилях legacy-pt/es для отката; одновременно с общим их не запускают.
Обычный `docker-compose up -d` запускает только общий монитор.
Общий сервис разворачивается отдельно от издателя и не обращается к WordPress.
Входная `RACES` доступна только для чтения. Результаты — существующая `Missing races`:
COUNTRY, Источник, Название, Дата, Ссылка, Координаты, Регион, Город.
Неполученные поля остаются пустыми; исходный PT-алгоритм сбора не заменён агентом.

Скопируйте `.env.example` в `.env`, перенесите существующие ключи Google/OpenCage
и авторизованную Telegram-сессию. `GOOGLE_CREDENTIALS_PATH=/app/google-credentials.json`,
`TELEGRAM_SESSION_PATH=/app/session.session`. Не коммитьте доступы и историю.

```bash
docker-compose build race-monitor-unified
# Регрессия в том же образе:
docker run --rm --entrypoint python racefinder-monitor-unified:latest -m pytest -q
# Проверка всех сайтов без записи таблиц/истории и без Telegram:
docker-compose run --rm -e DRY_RUN=true race-monitor-unified python -m app.main
# Ежедневная работа, только этот сервис:
docker-compose up -d --no-deps race-monitor-unified
```

Расписание общего режима: **00:15 Europe/Moscow**, без запуска при старте.
`restart: unless-stopped` восстанавливает контейнер после сбоя процесса/перезапуска
Docker. Состояние и дата завершённого прохода сохраняются в `data/unified/`.
После перезапуска выполненный день не повторяется, пропущенное расписание
догоняется; файл блокировки запрещает параллельные проходы. Каждый источник
работает в отдельном процессе с лимитом `SOURCE_TIMEOUT_SEC` (по умолчанию 3600).
Сбой одного источника сохраняет его прежний список, не блокируя остальные.
Отчёт `logs/unified/latest.json` содержит ошибки/счётчики; Docker healthcheck
контролирует свежесть последнего прохода (36 часов).

В Telegram отправляется один общий дайджест за день: PT/ES-кандидаты, новые
события, ошибки источников и ссылка на общую вкладку. Уведомлёнными события
помечаются только после успешной отправки. Повторный проход в тот же день
обновляет список без повторного дайджеста. При неудачной отправке история
уведомлений не меняется. Старые PT-ключи сохраняют прежнюю URL-семантику;
новые ключи содержат страну, URL и дату, если источник её предоставляет.

Однократная миграция выполняется **после остановки старых мониторов**, до включения
общего расписания, с пустым новым STATE_PATH:

```bash
python -m app.migrate_unified --pt-state /legacy-pt/notified.json --es-state /legacy-es/notified.json
# Просмотр отчёта выше; затем тот же вызов с --apply.
```

Команду запускают внутри общего Docker-образа с read-only томами старой истории,
новым постоянным томом `/app/data` и действующими Google-доступами.
Миграция сохраняет исходные JSON целиком и снимки обоих списков в
`data/unified/migration-backup/`, скрытую PT-копию и прежнюю ES-вкладку (архив).
Общая вкладка сохраняет прежний gid PT. Повторная миграция при наличии нового
состояния запрещена. Автоматического отката листов нет: при ошибке необходимо
проверить архивы, прежде чем включать расписание.

Ниже описаны прежние раздельные режимы; их расписания не относятся к общему.

## Структура проекта

- `app/` — исходный код приложения (точка входа `app/main.py`).
- `tests/` — минимальные тесты.
- `requirements.txt` — зависимости Python.
- `Dockerfile` — инструкция для сборки контейнера.
- `docker-compose.yml` — запуск через Docker Desktop.
- `.env.example` — пример конфигурации.

## Прежний запуск через Docker Desktop

```bash
docker compose build
docker compose up -d race-monitor
```

## Локальный запуск (без Docker)

```bash
./run_local.sh
```

## Расписание прежнего PT-контейнера
Скрипт запускается автоматически каждый день в 06:02 по Лисабону (Europe/Lisbon) без cron, через внутренний цикл ожидания.

## Тестовый запуск при старте прежнего PT-контейнера
При старте контейнера выполняется один тестовый запуск. Отключается через `RUN_SMOKE_ON_START=false`.

## Развертывание на сервере

1. Установить Docker и Docker Compose на сервер.
2. Склонировать репозиторий и подготовить `.env` и `google-credentials.json`.
3. Запустить контейнер: `docker compose run --rm race-monitor`.
4. Для расписания настроить cron на сервере, который будет выполнять команду из пункта 3 каждые 2 дня.

## Развертывание через git на сервере

```bash
git clone https://github.com/kodjooo/parser-of-racer.git
cd parser-of-racer
cp .env.example .env
# Заполнить .env и добавить google-credentials.json
docker compose build
docker compose up -d race-monitor
```

## Telegram (личный аккаунт)
Для отправки сообщений используется Telethon и сессия аккаунта.
Первый запуск попросит код подтверждения и, при необходимости, пароль 2FA.
Для сервера без интерактива используйте заранее созданную сессию:
1) запустите локально и пройдите вход;
2) перенесите файл сессии (`TELEGRAM_SESSION_PATH`) на сервер или используйте `TELEGRAM_SESSION_STRING`.

## Лист Missing races
Скрипт очищает и заполняет лист `Missing races` новыми ссылками и источниками на каждом запуске.

## Испанский мониторинг

Португалия остаётся режимом по умолчанию. Для Испании задайте `MONITOR_COUNTRY=es`,
`ES_MISSING_WORKSHEET_NAME=Missing races ES` и согласованный `ES_SOURCES_JSON`.
Каждый источник задаётся объектом `name`, `url` (HTTPS-календарь или sitemap),
`event_path_regex` (пути карточек). Адаптер читает Event/SportsEvent JSON-LD,
оставляет будущие события с явно указанной Испанией и проверяет известные записи
общего листа по COUNTRY (пустые старые значения означают Португалию).
Для подтверждённых источников используются отдельные адаптеры, описанные ниже.
Произвольные источники без JSON-LD требуют отдельной реализации.
`DRY_RUN=true` читает историю и пишет кандидатов только в лог, без изменения таблиц
и отправки Telegram. Испанский список хранится отдельно от португальского.
Любая ошибка источника или превышение лимита обхода останавливает испанский запуск
до изменения списка. Повторы сравниваются по URL и названию/дате/городу;
другие известные годы издания и страны не исключают новое событие.

## Общая таблица и независимые страны

История обеих стран хранится в одной вкладке `RACES` с `COUNTRY`. PT-монитор
сравнивает только португальские строки (включая старые пустые COUNTRY), ES — только
испанские. Статус публикации не определяет известность: любое событие в таблице
уже известно. Результаты разделены: `Missing races PT` и `Missing races ES`.
Compose сохраняет PT по умолчанию, ES включается явно профилем `es` после проверки
доступности обоих источников с сервера: `docker compose --profile es up -d --build`. Расписания независимы:
`PT_SCHEDULED_HOUR/MINUTE`, `ES_SCHEDULED_HOUR/MINUTE`; время — Europe/Lisbon.
ES использует отдельные каталоги data/es и logs/es, лимит ES_MAX_PAGINATION_PAGES.
Повторные ES-уведомления отсеиваются по URL+дате издания; список кандидатов при этом
остаётся полным. DRY_RUN не создаёт вкладок и не меняет историю уведомлений.

## Подтверждённые испанские источники

Антонио подтвердил Running.life и RockTheSport. Конфигурация двух адаптеров
есть в .env.example. ES остаётся отдельным opt-in профилем Docker.
Running.life обходится по страницам календаря (лимит 120); RockTheSport — через
публичный API с фильтром Испании, полной пагинацией и выбором беговых дисциплин.
Собираются название, ссылка, дата и доступная география/координаты; цены, варианты
и тексты по-прежнему заполняет человек. Отсутствующая география остаётся пустой.

Проверка без Google/Telegram/WP: `python -m app.discover_spain --output /tmp/es-candidates.json`.
Команда читает все страницы; при ошибке итоговый файл не перезаписывается.
Для проверки против истории добавьте `--known-json /tmp/races-snapshot.json`.
На сервере выполнять внутри образа монитора, не меняя запущенный PT-контейнер.

Оба источника полностью проверены с рабочего сервера 29.10.2026: Running.life —
81 страница, RockTheSport — 6 страниц. Источники получают честный User-Agent
`RaceFinderMonitor/1.0 (+https://racefinder.es)` (ES_HTTP_USER_AGENT). Стандартное
имя requests получало 403; маскировка под браузер и обход защит не используются.
При новой блокировке/ошибке список не перезаписывается. ES-профиль остаётся
выключенным до клиентской проверки и подтверждения языков.

Испанский сервис имеет restart unless-stopped; TELEGRAM_NOTIFICATIONS_ENABLED=false отключает только отправку Telegram, не обновление списка новых. Неотправленные события не отмечаются отправленными.

ES использует отдельный Dockerfile.es на Python 3.11 без Playwright. PT-образ не меняется; браузерные импорты выполняются только в PT-ветке main. Реальные запросы проверяются именно в ES-образе, не только в диагностическом окружении издателя.

Рабочий ES checkout на сервере: `/usr/local/sheets-to-wp-racefinder/parser-of-racer-es`.
Запуск: `docker-compose -p racefinder-es --profile es up -d --no-deps race-monitor-es`.
Настроено 07:02 Europe/Lisbon, `RUN_SMOKE_ON_START=false`, Telegram отключён.
Проверка 07.11.2026 в самом ES-контейнере: Running.life 1705 событий / 86 страниц,
RockTheSport 346 беговых / 6 страниц; после дедупа в Missing races ES записано 1964.
RACES дополнен только заголовком COUNTRY в конце; старые пустые страны — PT.
Полная регрессия PT: 66 тестов; применимые ES-тесты без Playwright: 62.
